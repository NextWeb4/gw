# HxHwang Gw 管理系统使用说明书

版本：v0.3.1  
适用范围：公开演示版、互联网版、内网版  
在线演示：[https://nextweb4.github.io/gw/](https://nextweb4.github.io/gw/)

HxHwang Gw 用于管理任务、文件收发、公文草稿、周报和历史数据。系统采用本地优先设计：业务记录先保存在当前设备的 IndexedDB 中；只有内网版在用户手动建立会话后支持私有同步，AI 请求也必须由用户逐次触发。

## 使用前先看

- 桌面宽屏从左侧导航进入模块；手机或窄屏从底部导航进入。模块名称和功能一致。
- 页面右上角的刷新按钮只重新读取本机数据，不等于保存、同步或从服务器下载。
- 页面短暂提示显示操作结果；提示消失不影响数据。遇到失败提示时，先不要重复导入或删除，应按本说明书的故障处理章节核查。
- 本说明书中的“本机”指当前浏览器配置或当前桌面客户端用户数据目录，不代表电脑上所有账号和浏览器都共享数据。
- 所有删除按钮当前均直接执行，不提供回收站。删除前应先在“数据迁移”导出快照。

| 导航模块 | 主要用途 | 可写操作 | 数据去向 |
| --- | --- | --- | --- |
| 工作台 | 查看任务、到期事项和记录总数 | 仅跳转 | 不产生新记录 |
| 任务管理 | 管理交办事项、阶段、单位、小结和附件 | 新建、编辑、删除 | 本机任务库 |
| 文件收发 | 登记收文、发文、承办人和附件 | 新建、编辑、删除 | 本机文件库 |
| 公文写作 | 套用模板、导入、编辑、保存和导出文稿 | 编辑主草稿、自定义格式 | 本机草稿与设置 |
| 周报生成 | 按日期汇总已录入事实 | 新建、编辑、保存、删除、导出 | 本机周报库 |
| 历史档案 | 查看旧系统不可变原件 | 只读、下载可用附件 | 本机只读档案库 |
| 数据迁移 | 导入旧数据、备份和恢复 | 导入、恢复、导出 | 本机全部业务库 |
| 关于与设置 | 查看版本并配置分版服务 | 会话级连接、同步或 AI 请求 | 连接信息不写入快照 |

## 1. 版本选择与下载

| 版本 | 适用场景 | AI 连接方式 | 私有同步 | 真实附件与历史导入 |
| --- | --- | --- | --- | --- |
| 公开演示版 | 浏览器体验、脱敏样例演示 | 不提供 | 不提供 | 禁用 |
| 互联网版 | 可访问公网模型接口的个人或非涉密办公设备 | 用户填写 OpenAI 兼容请求地址和 API Key | 不提供 | 桌面版支持 |
| 内网版 | 单位内部网络、内部模型和私有服务 | 只通过内部 HxHwang Gw API 网关 | 手动同步 | 支持 |

从 [GitHub Releases](https://github.com/NextWeb4/gw/releases/latest) 下载。每种架构分别提供互联网版和内网版；文件名包含 `internet` 或 `intranet`，不要只凭系统架构判断版本。

- Windows 10/11 x64：选择 `*-internet-x64-setup.exe` 或 `*-intranet-x64-setup.exe`。
- Windows 10/11 ARM64：选择 `*-internet-arm64-setup.exe` 或 `*-intranet-arm64-setup.exe`。
- Debian/Ubuntu amd64：选择 `*-internet-amd64.deb`、`*-intranet-amd64.deb`，或对应 `x86_64.AppImage`。
- Debian/Ubuntu arm64：选择 `*-internet-arm64.deb`、`*-intranet-arm64.deb`，或对应 `arm64.AppImage`。
- Windows 可在“设置 > 系统 > 系统信息 > 系统类型”查看架构；Debian 可执行 `dpkg --print-architecture`。
- `.deb` 推荐使用 `sudo apt install ./文件名.deb` 安装，以便系统同时处理运行依赖。
- AppImage 首次使用前执行 `chmod +x 文件名.AppImage`，再运行该文件。

互联网版和内网版的数据格式相同，可以通过“数据迁移 > 导出快照”转移本地数据；API Key、访问码和会话令牌不会写入快照。

### 1.1 Windows 安装

1. 下载与系统架构、联网方式一致的 `setup.exe`。
2. 在 PowerShell 中执行 `Get-FileHash .\安装包文件名.exe -Algorithm SHA256`，与 Release 的 `SHA256SUMS.txt` 对照。
3. 双击安装包，按安装向导选择当前用户安装位置并完成安装。
4. 当前安装包尚未进行 Authenticode 代码签名，Windows 可能显示“未知发布者”。只应从本项目 Release 下载并先核对 SHA-256；正式组织部署前应补充代码签名。
5. 首次启动后进入“关于与设置”，核对版本、桌面运行模式和互联网版/内网版标识。

不要在同一用户目录中同时运行两个版本进行同一条记录的编辑。需要切换版本时，先退出原客户端并导出快照。

### 1.2 Debian 安装

1. 执行 `dpkg --print-architecture`，确认是 `amd64` 或 `arm64`。
2. 下载对应版本的 `.deb`，并将 `SHA256SUMS.txt` 放在同一目录。
3. 可执行 `sha256sum 文件名.deb` 后人工对照清单；若已下载清单列出的全部 Release 资产，也可执行 `sha256sum -c SHA256SUMS.txt`。
4. 执行 `sudo apt install ./文件名.deb`。不要使用忽略依赖的强制安装参数。
5. 从应用菜单启动，或按安装后的可执行入口启动，再到“关于与设置”核对版本。

AppImage 适合免安装试用；`.deb` 更适合由系统管理依赖、升级和卸载。Debian 10 只作为兼容目标，日常使用优先 Debian 12。

### 1.3 公开演示版

访问 [https://nextweb4.github.io/gw/](https://nextweb4.github.io/gw/)。首次加载完成后可使用已缓存的演示资源，但浏览器清理站点数据会同时清除本地记录和离线缓存。公开演示版只能使用虚构样例，不得录入真实材料。

## 2. 首次使用

1. 打开系统后先查看左侧或移动端底部的版本标识，确认是“公开演示版”“互联网版”或“内网版”。
2. 进入“任务管理”和“文件收发”检查内置样例，了解字段结构。
3. 桌面版或内网 Web 用户进入“数据迁移”导入旧系统 JSON；首次导入后立即检查迁移报告。
4. 进入“关于与设置”确认版本、构建时间、运行模式和数据位置。
5. 正式录入前在“数据迁移”导出一次空白或样例快照，确认浏览器或终端允许下载文件。

顶部“刷新本地数据”只重新读取当前设备的数据，不会自动连接服务器。页面提示会短暂显示在右下角；右下角不再保留无操作价值的“未连接 AI”常驻模块。

## 3. 工作台

工作台用于快速查看当前数据，不在此处修改记录。

- “进行中任务”统计所有未办结任务。
- “近七日到期”显示截止日期临近且尚未办结的任务。
- “登记文件”和“历史档案”显示当前本地库记录数量。
- “任务队列”展示最近的任务、中文状态和截止日期，点击“查看全部”进入任务管理。
- “登记新文件”“开始写作”“导入旧数据”可直接进入对应模块。

## 4. 任务管理

### 4.1 新建任务

1. 点击“任务管理 > 新建任务”。
2. 填写任务名称。该字段不能为空。
3. 在“状态”中选择中文状态：`未启动`、`进行中`、`已完成`、`已超期`。
4. 填写截止日期和交办日期。日期必须是 `YYYY-MM-DD`，年份固定为四位，允许范围为 1900-01-01 至 9999-12-31；六位年份、无效日期和不存在的日期不会写入记录。
5. 填写工作类目、任务来源和交办人。
6. 点击“保存任务”。保存成功后返回列表，交办人和配合单位会进入常用项。

### 4.2 复用人员和单位

- “交办人”“承办人”“来源单位”和配合单位输入框会列出已保存的常用项。
- 输入新人员后可点击输入框右侧的加号立即加入常用项；保存任务或文件时也会自动加入。
- 任务中保存的交办人可以在文件的“承办人”中复用；来源单位、任务配合单位和阶段配合单位共享单位常用项。
- 相同文本会去重并按中文排序。当前版本不建立人员账号，只保存名称文本。

### 4.3 配合单位和任务阶段

1. 点击“添加单位”。
2. 输入或选择单位名称，并设置 `已通知`、`待反馈`、`进行中` 或 `已完成`。
3. 点击“添加阶段”录入阶段名称。
4. 每个阶段可继续添加自己的配合单位及状态。
5. 删除按钮只移除当前编辑记录中的该行，不会删除常用项或其他任务中的单位。

### 4.4 一键生成工作小结

1. 先填写任务名称、状态、交办人、配合单位、截止日期和备注。
2. 选择“小结模板”：进展小结、协同推进或办结小结。
3. 点击“一键生成小结”。系统只根据当前任务字段确定性生成文字，不调用 AI。
4. 在“工作小结”中人工核对和修改，再保存任务。

如果输入字段为空，模板会使用中性占位表述。生成结果不会虚构完成比例、金额、人数或未录入的事实。

### 4.5 任务附件

- 桌面端和内网 Web 可选择附件，单个文件上限 8 MB，内容保存在本机。
- 点击下载图标可下载附件；点击解除关联只解除当前任务引用，不会静默删除其他记录可能使用的附件。
- 公开演示版禁用真实附件。

### 4.6 查找、编辑和删除任务

- 搜索框同时匹配任务名称、工作类目和交办人；清空搜索框恢复全部任务。
- 点击任务行末的铅笔按钮打开编辑抽屉。修改后必须点击“保存任务”；点击“取消”、关闭按钮或抽屉外区域不会保存本次修改。
- 点击行末的删除按钮会立即删除任务记录，当前没有回收站或撤销功能。附件实体不会随任务静默删除，但原任务关系无法恢复，除非重新导入删除前的快照。
- 列表中的“附件 0/1/…”表示当前任务关联数量，不表示附件内容一定仍可下载；迁移数据应在历史档案中抽查校验值和可用状态。

## 5. 文件收发

1. 点击“文件收发 > 登记文件”。
2. 填写文件标题、文件类型、成文日期、发文字号、来源单位和承办人。
3. 设置登记状态：`待登记`、`已登记`、`已办结` 或 `归档`。
4. 按实际情况填写安全级别、工作类目、文件归类、发送范围和备注。
5. 需要时添加本机附件，再点击“保存文件”。

文件列表支持按标题、文号和来源单位搜索。成文日期同样执行四位年份和真实日历日期校验。来源单位与承办人保存后可在后续任务和文件中复用。

- 点击文件行末的铅笔按钮编辑；必须点击“保存文件”才会写入修改。
- 点击删除按钮会立即删除文件记录，不提供回收站；先导出快照再进行批量整理。
- 附件规则与任务一致：单个不超过 8 MB，可下载或解除当前文件的关联；公开演示版禁用真实附件。
- 文件标题和成文日期是保存边界的必填项。`2026-02-30`、六位年份或 1900 年以前的日期都会被拒绝。

## 6. 公文写作

### 6.1 使用内置模板

1. 点击“公文写作”。
2. 在左侧“结构选择”中搜索文种或模板名称。
3. 点击模板后，系统把模板标题和结构载入编辑器。
4. 在中间纸张区域修改标题和正文。
5. 右侧“落笔检查”显示结构、长句和事实复核提醒；规则同时标注来源类型、版本和严重程度。

官方规范属于确定性规则，AI 和教材建议都不能覆盖它。正式发文前仍需按本单位现行制度审核。

### 6.2 导入文档

点击“导入文档”可选择：

- DOCX：使用 Mammoth 在本机转换为可编辑 HTML。
- HTML/HTM：删除脚本、表单、嵌入对象、事件属性和非允许标签后导入。
- TXT：按非空行转换为段落。

单个导入文件上限 10 MB。导入不会上传文件；转换会保留常用标题、段落、列表、引用、粗体和斜体，但 Word 页眉页脚、复杂表格、文本框、批注、分页和精确字体可能丢失。导入后必须复核标题、段落层级、事实和版式。

### 6.3 保存版本和自定义格式

- “保存版本”保存当前主草稿并递增版本号；页面重载后继续显示该版本。
- 当前“保存版本”维护的是一份主草稿及其版本计数，不保存每次修改的可回退副本。进行大改、导入或切换模板前，应先导出 DOCX 或本地快照。
- “保存自定义格式”把当前标题、文种和正文结构保存为本机模板。
- 保存后可在“结构选择”中搜索自定义格式，来源标识为“本机自定义”。
- 再次套用自定义格式会替换当前编辑器内容，操作前应先导出需要保留的 DOCX 或本地快照。
- 自定义格式随本地快照导出和恢复，不会上传到公开知识包。

### 6.4 导出 DOCX/PDF

- “导出 DOCX”生成 A4 Word 文件，并写入作者元数据 `HaoXiangHwang`。
- 桌面端“导出 PDF”打开系统保存对话框；Web 端打开浏览器打印流程，选择“另存为 PDF”。
- 系统仅引用字体名称，不捆绑未授权字体。缺少方正小标宋、仿宋、黑体或楷体时会回退，正式使用前必须在 Word 或 PDF 中检查分页和字体。

## 7. 周报生成

1. 点击“周报生成”。
2. 选择开始日期和结束日期，日期必须是四位年份且开始日期不晚于结束日期。
3. 点击“重新汇总”。系统按已有任务日期、状态、工作小结和文件日期确定性生成正文。
4. 修改周报标题和正文，补充经核实的事实。
5. 点击“保存版本”。右侧“已保存周报”列表可重新打开已保存的周报记录。
6. 使用“导出 DOCX”或“导出 PDF”输出 A4 文档。

右侧实际是“已保存周报”列表：同一周报再次保存会递增版本号并更新该记录，不会保留每一版正文的可回退副本；需要留存阶段稿时，应先导出 DOCX 或快照。“新建”会回到当前周默认范围，未保存修改不会自动另存。

周报不会从备注之外推断新事实，也不会自动调用 AI。删除按钮会立即删除选中的新周报记录；历史迁移的旧周报仍在“历史档案”中只读保留。

## 8. 历史档案

该模块只读展示旧系统中的会议、外出、用章、物资、周报、Skill、配置和未映射字段。

- 点击“查看迁移原始字段”可查看 `legacyPayload` 的纯文本 JSON。
- 历史 HTML 和 Skill 不会作为网页执行。
- 有本地正文和校验值的历史附件可以下载；内容缺失的附件按钮会禁用。
- 要修改历史事项，应在新系统中新建任务或文件，不要直接改写迁移原件。

## 9. 数据迁移与备份

### 9.1 导入旧数据

桌面端和内网 Web 支持两份历史 HTML 导出的 JSON，以及 `hxhwang-gw-local-v1` 本地快照。

1. 点击“数据迁移 > 选择 JSON 文件”。
2. 等待“迁移报告”出现。
3. 对照原系统检查任务、文件、会议、外出、用章、物资、周报、Skill、配置和附件数量。
4. 阅读全部警告，重点检查重复 ID、悬空附件和无法区分的来源版本。
5. 进入“历史档案”抽查原始字段和附件。

导入不会先清空现有数据；同 ID 同类型记录按导入内容更新，跨类型同 ID 会拒绝覆盖。公开 Pages 不允许导入真实业务 JSON或恢复快照。

### 9.2 导出和恢复快照

- 点击“导出快照”下载当前任务、文件、草稿、周报、历史档案、设置、常用项、自定义格式和附件。
- 更换电脑、浏览器、版本或清理站点数据前必须先导出快照。
- 恢复后查看报告，再逐个模块抽查。快照中不包含 API Key、访问码、会话令牌或服务端密钥。

建议至少在首次正式录入、批量导入前、批量删除前、升级或切换版本前各导出一次，并把快照复制到受控备份位置。仅看到“下载完成”不足以证明备份可用，应在测试浏览器配置或备用设备中执行一次恢复抽查。

## 10. 内网版设置与 AI

内网版只通过内部 HxHwang Gw API 使用同步和 AI，不提供用户直连公网模型的入口。

1. 进入“关于与设置”。
2. 在“内部 API 地址”填写单位部署地址。允许 HTTPS；本机调试可使用 `http://127.0.0.1:端口` 或 `http://localhost:端口`。
3. 填写一次性访问码，点击“建立会话”。建立成功后访问码输入框会清空。
4. 点击“同步业务数据”手动同步任务、文件、草稿、周报和引用附件。系统不会后台自动同步。
5. 点击“获取内部模型”，从网关返回的模型列表中选择模型。
6. 填写用途和待处理材料，点击“生成脱敏预览”。
7. 人工修改并确认脱敏预览，再点击“确认发送到内部 AI”。

内部模型提供方的 API Key 只存放在私有服务端。客户端只能获得模型名称和结果，不能读取服务端密钥。当前共享访问码模式仅适合演示或受控内网，不应宣称为完整生产认证。

## 11. 互联网版设置与 AI

互联网版可连接 OpenAI 兼容接口，不提供私有业务同步。

1. 进入“关于与设置 > 兼容 API 配置”。
2. 填写请求地址。系统同时接受 `https://服务地址/`、`https://服务地址/自定义路径/` 和以 `/v1` 结尾的地址，不会重复拼接 `/v1`。
3. 填写 API Key。Key 只保留在当前运行会话内存中，不写入 IndexedDB、配置、日志或快照。
4. 点击“获取 AI 模型”，选择返回的模型。
5. 填写用途和待处理材料，生成并人工检查脱敏预览。
6. 点击“确认本次互联网请求”后才会发送。结果只读展示，不自动覆盖原稿或确定性规则。

浏览器互联网版要求模型服务允许 CORS；桌面互联网版通过受限 Electron IPC 请求。请求地址只允许 HTTPS，本机调试例外允许回环 HTTP；禁止 URL 内嵌用户名和密码，禁止自动跟随重定向，响应体上限为 2 MB。

严禁向公网模型发送涉密材料、个人敏感信息或未经授权的内部文件。本地脱敏只能辅助识别手机号、邮箱、身份证号和常见姓名标签，不能证明内容已经匿名化。

## 12. 常见问题

### 日期无法保存

检查是否为真实的 `YYYY-MM-DD` 日期。六位年份、2026-02-30、空的必填日期、早于 1900 年或开始日期晚于结束日期都会被拒绝。

### 获取不到模型

- 确认版本是否正确：内网版使用“获取内部模型”，互联网版使用“获取 AI 模型”。
- 检查地址是否包含正确的反向代理路径，并确认服务实现 OpenAI 兼容的模型列表接口。
- 浏览器互联网版还要检查服务端 CORS；桌面版不依赖浏览器 CORS。
- 401/403 通常表示访问码或 API Key 无效；404 通常表示请求地址路径不正确；502 表示网关无法从模型服务取得正常响应。

### 数据在另一台电脑看不到

公开演示版和互联网版默认只保存本机数据。使用“导出快照”转移；内网版也必须手动建立会话并点击同步，系统不会自动上传。

### 导入 DOCX 后版式变化

DOCX 导入目标是提取可编辑结构，不是像素级复刻 Word。复杂表格、页眉页脚、文本框和分页需在导入后重新检查。最终以导出的 Word/PDF 实机预览为准。

### 卸载后数据是否保留

不要依赖卸载行为保留数据。卸载、清理浏览器数据或更换用户配置前，先导出本地快照并验证文件可读取。

### 页面仍显示旧版本

先核对地址必须是 `https://nextweb4.github.io/gw/`，再关闭该站点的其他标签页并刷新。若仍显示旧版本，可在浏览器站点设置中清除该站点缓存后重新打开；清除前必须导出本地快照，因为站点数据和业务记录可能一起被删除。

### 附件无法添加或下载

- 公开演示版不允许添加真实附件；请使用桌面客户端或内网 Web。
- 单个文件超过 8 MB 会被跳过并提示；可先在受控环境中压缩或拆分。
- 历史档案按钮禁用表示迁移包只有引用而没有本地正文或校验值，系统不会伪造下载内容。
- 浏览器阻止下载时，允许当前站点下载后重试；不要为解决下载问题关闭系统整体安全防护。

### 导入 JSON 失败

确认文件是两版旧系统导出的 JSON 或 `hxhwang-gw-local-v1` 快照，而不是旧 HTML 文件本身。不要手工删改 `_meta`、记录 ID、附件 Data URL 或快照 `format`；先保留原件，再复制一份用于排错。

### 误删记录

当前没有回收站。停止继续编辑，找到删除前最近一次快照，在测试配置中恢复并核对目标记录；确认无误后再决定是否恢复到正式配置。恢复是合并/更新操作，不会自动先清空现有数据。

## 13. 关于与设置

- 顶部信息卡显示作者、版本、构建时间、运行模式、数据位置、周报数量、版权和规则包版本。
